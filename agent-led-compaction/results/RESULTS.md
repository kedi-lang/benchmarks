# Phases 1–5 — results

Generated by `summarize.py` from `records/`; do not edit by hand.

## Key

Phases 1–5 are exploratory: they were designed and run before any pre-registration, and many comparisons were made, so their p-values describe these runs and test no hypothesis (the pre-registered tests are in `PHASES_6_8.md`). The model is `gpt-6-luna` at reasoning effort medium. Every strategy compacts at an estimate of 18K tokens. Seeds 1–5 give the same five scenarios to every strategy. Kedi and library versions per phase are in `environment.json`. The `calls` and `compactions` columns list one value per seed, in seed order.

| strategy | what it does |
|---|---|
| `none` | No compaction: the whole history is sent on every request. |
| `B1` | Truncation: Kedi drops older exchanges and keeps the last 2. |
| `B2` | Stateless summary: a separate request summarizes the dropped exchanges as free text; the last 2 stay verbatim. |
| `B3` | Stateless structured summary: a separate request summarizes the dropped exchanges as JSON (rules, facts, pending work, summaries); the last 2 stay verbatim. |
| `native` | Provider compaction: OpenAI's server-side compaction (Responses `context_management`) at the same threshold. |
| `A1-fixed` | Agent fork, fixed retention: as A1, but the last 2 exchanges stay, not the ones the agent chooses. |
| `A1` | Agent fork: the agent itself, seeing its full context, writes a JSON summary (rules, facts, pending work, summaries) and chooses which exchanges stay verbatim. |
| `A1-free` | Agent fork, free text: the agent itself, seeing its full context, summarizes what it drops as free text and chooses which exchanges stay verbatim. |

An exchange is one model turn with the tool calls it made and their results.

Every task: the agent reads logs one `read_log` call at a time (about 6.7K tokens each) and reports the incident ids and one owner. Rules in the prompt: ignore service `legacy`; report ids in uppercase, ids only; the owner is the owner of the reported incident with the highest current severity.

| task | twist |
|---|---|
| `t1` | Task 1 (`task1` in file names): 8 logs; every rule is in the prompt. |
| `rev` | 8 logs. An UPDATE raises an early incident's severity, a RETRACT in the last log withdraws one, and a mid-task POLICY CHANGE adds a service to ignore, including incidents already read. The change is not in the protected prompt. |
| `long` | As rev, with 20 logs (about 135K tokens) and many compactions. |
| `big` | 8 logs; one log of about 34K tokens is larger than the threshold. |

| column | meaning |
|---|---|
| n | Runs, one per seed. |
| strict | Pass: exactly the expected incidents, ids only, in the required case, and the correct owner. |
| lenient | The expected incident ids and owner, formatting ignored. |
| total input | Input tokens of every request in the run, compaction requests included; cached tokens count. |
| calls | Requests in the run, compaction requests included. |
| compactions | Compaction events in the run. |
| errors | Runs that ended in an error. Request-limit and token-budget errors count as failures. |
| policy viol. | Incidents reported from a service the mid-task POLICY CHANGE excluded (rev, long). |
| retracted reported | Retracted incidents still reported (rev, long). |
| missing | Expected incidents not reported, summed over the runs. |
