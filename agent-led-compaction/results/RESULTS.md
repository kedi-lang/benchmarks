# Results — phases 1–10

Generated by `agent_compaction/summarize.py` from `records/`; do not edit by hand.

## Key

Every strategy compacts at an estimate of 18K tokens. The model is `gpt-6-luna` at reasoning effort medium unless a section names another. Each section names its records, its seeds and whether it was pre-registered: phases 6, 9 and 10 were; phases 1–5, 6b, 7 and 8 are exploratory, with many comparisons, so their p-values describe the runs and test no hypothesis. Seeds give every strategy the same scenarios. Token columns are medians over the runs that completed; calls and compactions show the median and, in brackets, the maximum. Paired comparisons use the exact McNemar test on (task, seed) pairs and drop a pair with a missing side; the difference in pass rate comes with a 95% confidence interval for paired proportions (Newcombe's method 10). That interval is a score approximation, not the inverse of the exact test, so near the 5% level the two can disagree; the pre-registered tests are the p-values. Role: *primary* tests a pre-registered hypothesis; *secondary* and *descriptive* comparisons were named in the pre-registration without being hypotheses; *exploratory* ones were not pre-registered. Kedi and library versions per phase are in `environment.json`.

| strategy | what it does |
|---|---|
| `none` | No compaction: the whole history is sent on every request. |
| `B1` | Truncation: Kedi drops older exchanges and keeps the last 2. |
| `B2` | Stateless summary: a separate request summarizes the dropped exchanges as free text; the last 2 stay verbatim. |
| `B3` | Stateless structured summary: a separate request summarizes the dropped exchanges as JSON (rules, facts, pending work, summaries); the last 2 stay verbatim. |
| `native` | Provider compaction: OpenAI's server-side compaction (Responses `context_management`) at the same threshold. |
| `native+reassert` | native, and the runtime also restates every instruction change verbatim just before the current exchange. |
| `A1-fixed` | Agent fork, fixed retention: as A1, but the last 2 exchanges stay, not the ones the agent chooses. |
| `A1` | Agent fork: the agent itself, seeing its full context, writes a JSON summary (rules, facts, pending work, summaries) and chooses which exchanges stay verbatim. |
| `A1-free` | Agent fork, free text: the agent itself, seeing its full context, summarizes what it drops as free text and chooses which exchanges stay verbatim. |
| `reset-det` | Deterministic reset: at the threshold and at every instruction change, the runtime replaces the history with the protected prompt, a checkpoint it builds itself and the current exchange. |
| `reset-fork` | A1-free, also triggered at every instruction change (the timing of reset-det). |

An exchange is one model turn with the tool calls it made and their results.

Every task: the agent reads logs one `read_log` call at a time (about 6.7K tokens each) and reports the incident ids and one owner. Rules in the prompt: ignore service `legacy`; report ids in uppercase, ids only; the owner is the owner of the reported incident with the highest current severity.

| task | twist |
|---|---|
| `t1` | Task 1 (`task1` in file names): 8 logs; every rule is in the prompt. |
| `rev` | 8 logs. An UPDATE raises an early incident's severity, a RETRACT in the last log withdraws one, and a mid-task POLICY CHANGE adds a service to ignore, including incidents already read. The change is not in the protected prompt. |
| `long` | As rev, with 20 logs (about 135K tokens) and many compactions. |
| `big` | 8 logs; one log of about 34K tokens is larger than the threshold. |
| `override` | Held-out task, 8 logs: a CHANGE line in log 5 makes the owner the owner of the reported incident with the lowest current severity, not the highest. |
| `format` | As override, but the change makes incident ids lowercase. |
| `scope` | As override, but the change limits the report to billing, auth and payments, including incidents already read. |
| `-early` | Suffix on a held-out task: the same kind of change arrives in log 2, before the first compaction (control). Its incidents are drawn separately, so for the same seed it is a different scenario from the task without the suffix, not only a different timing. |
| `override-inject` | override, with the change marked `[authorized by the audit lead]`, plus an unmarked fake FORMAT CHANGE in log 7 that must be ignored. |

| column | meaning |
|---|---|
| pass | Strict passes out of the runs that completed. |
| lenient | The expected incident ids and owner, formatting ignored. |
| missing (infra) | Runs lost to infrastructure failures (usage or rate limit, timeout, connection error, HTTP 503) after the one allowed rerun. They count neither as passes nor as failures. |
| policy viol. | Incidents reported from a service the mid-task POLICY CHANGE excluded (rev, long). |
| change applied | Runs whose answer follows the changed instruction (held-out tasks): the owner of the lowest-severity incident, in any letter case (override), every id in lowercase (format), only billing, auth and payments incidents (scope). |
| total input | Input tokens of every request in the run, compaction requests included; cached tokens count. |
| input per pass | Input tokens of all completed runs divided by their strict passes: what one correct report cost. |
| output | Output tokens of the run, compaction output included. |
| calls | Requests in the run, compaction requests included. |
| compactions | Compaction events in the run. |
| time | Wall-clock seconds per run, median over the completed runs. |
| difference | Left minus right pass rate in percentage points over the same pairs, with its 95% confidence interval. |
